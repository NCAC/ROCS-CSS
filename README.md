## 📦 Monorepo and Packages

The **rocs-monorepo** root is private (`private: true`) and uses pnpm workspaces `packages/*` ([pnpm-workspace.yaml](pnpm-workspace.yaml)).

| Package | Version | Contents and status |
| --- | --- | --- |
| [@rocss/rocs](packages/rocs/README.md) | 1.0.0 | ROCS specification, CLI/JavaScript validation API, and Stylelint/ESLint configurations. |
| [@rocss/sass-architecture](packages/sass-architecture/README.md) | 0.1.0 | **Documentation-only draft** reference architecture; no Sass mixins or runtime code. |
| [@rocss/sass](packages/sass/README.md) | 0.1.0 | **Private experimental Sass implementation** (`private: true`): seven mixins across four families; tests must be run and contracts reviewed before removing private status. |

See the [monorepo guide](docs/MONOREPO.md) and [contribution instructions](CONTRIBUTING.md).

The [French ROCS sources](docs/fr/) are authoritative; the [English documents](docs/en/) are translations. The Sass architecture draft has its sources in [packages/sass-architecture/docs/fr/](packages/sass-architecture/docs/fr/). Documentation copies in the `@rocss/rocs` package are generated by `pnpm run build` or the `prepack` hook: **never edit these copies directly**.

Canonical combinator sources live in [packages/sass/](packages/sass/): **13 SCSS files copied/adapted** from the initial local import directory. The initial import directory has been removed: `packages/sass` is the only source. The package includes an [actual copy of the MIT license](packages/sass/LICENSE).

The seven available mixins are `context.media`, `context.supports`, `context.container`, `state.pseudo-class`, `state.attribute`, `scope.ancestor`, and `part.pseudo-element`. Import each family with `@use "pkg:@rocss/sass/context"`, `/state`, `/scope`, or `/part`, enabling Dart Sass's Node package importer (≥ 1.71.0; CLI: `--pkg-importer=node`, API: `importers: [new NodePackageImporter()]`). `loadPaths: ["node_modules"]` remains an alternative; see the [package README](packages/sass/README.md#imports). After `pnpm install`, these imports resolve the local workspace; they do not imply npm publication.

The validator and API live in [packages/rocs/src/validator.js](packages/rocs/src/validator.js), with the CLI in [packages/rocs/bin/rocs.js](packages/rocs/bin/rocs.js) and configurations in [packages/rocs/stylelint.config.json](packages/rocs/stylelint.config.json) and [packages/rocs/eslint.config.js](packages/rocs/eslint.config.js). The [legacy CLI](tools/rocs-validate.js) remains available as a wrapper. **CSS is now included** alongside HTML, HTM, and SCSS in the scanned extensions: analysis remains **heuristic**, without template adapters (Twig, Vue, JSX, etc.) or a guarantee of complete compliance. SCSS sources and generated CSS are analyzed separately; human review is still required.

### Development from the repository

With Node.js ≥ 20, from the root:

```bash
pnpm install --frozen-lockfile
pnpm run build
pnpm test
pnpm run check
pnpm run pack:check
```

`pnpm run check` runs **build → test → lint → validate**. `pnpm run pack:check` inspects **all three archives**, including the private `@rocss/sass` workspace, using `pnpm pack --dry-run`; **it publishes nothing**. Private status prevents publication, not local archive creation with `pnpm pack`.

Tests have been added for Sass compilation (entry points and compositions), invalid arguments, and installation of all three archives outside the repository, including compilation from the installed package. **These tests still need to be run; their presence does not establish that they pass.**

**No package has been published at this stage; packages will be published under the `@rocss` npm organization.** Root release scripts were removed because the previous global release process does not fit independent versions. Any future publication is manual from the repository, after checks and verification of npm permissions; no CI publication is configured.

## 🎯 At a Glance

**ROCS** enforces simple and radical rules:

- ✅ **1 class per element** (no composition)
- ✅ **PascalCase for Blocks** (`BestSellersBooks`)
- ✅ **`data-*` reserved for JS-driven dynamic state/parameters**
- ✅ **Cascade restricted** (Block state → its own elements, plus explicit global context via `:where()`)
- ✅ **Preprocessors required** (mixins, no HTML helpers)
- ✅ **Semantic naming** (role/context, never appearance)

## 🚀 Quick Start

### 1. Stylelint (recommended)

```bash
npm install --save-dev stylelint stylelint-config-standard-scss
```

`.stylelintrc.json`:

```json
{
  "extends": "stylelint-config-standard-scss",
  "rules": {
    "selector-max-class": 1,
    "selector-no-qualifying-type": true,
    "no-descending-specificity": true,
    "selector-max-specificity": "0,3,0"
  }
}
```

### 2. HTML Test (optional)

```js
test("One class per element", () => {
  document.querySelectorAll("[class]").forEach(el => {
    expect(el.classList.length).toBeLessThanOrEqual(1);
  });
});
```

## 🆚 Why Not BEM/Atomic CSS?

| Issue | BEM | Atomic CSS | ROCS |
| ------- | ----- | ------------ | ------ |
| Unreadable double dashes | ❌ `.block__el--mod` | ✅ N/A | ✅ `.Block-element` |
| Style in HTML | ✅ No | ❌ **Massive** | ✅ No |
| Redesign without touching HTML | ✅ Yes | ❌ No | ✅ Yes |
| Predictable specificity | ✅ Yes | ⚠️ Variable | ✅ Yes (0,1,0) |

**Real horror case:**

```css
/* Seen in production */
.Context .blue { color: red !important; }
```

→ **Impossible with ROCS** (semantic naming required)

## 🧪 Quick Example

```html
<!-- ❌ Atomic CSS: style in HTML -->
<div class="flex items-center justify-between p-4 bg-blue-500 rounded shadow-md">
  <h3 class="text-lg font-bold text-white">Title</h3>
</div>

<!-- ✅ ROCS: semantic role/context (one class) -->
<section class="BestSellersBooks" data-slider-active="true">
  <h2 class="BestSellersBooks-title">Best sellers</h2>
  <div class="BestSellersBooks-slider">...</div>
</section>
```

```scss
// ROCS CSS (with preprocessor)
.BestSellersBooks-title {
  @include section_title();
}

/* JS-driven state/parameters via data-* (dynamic) */
.BestSellersBooks[data-slider-active="true"] .BestSellersBooks-slider {
  @include slider_enabled();
}
```

## 🛠 Core Rules

### 1. One class = one unique role/context

```html
<!-- ❌ Forbidden -->
<button class="btn btn-primary btn-large">

<!-- ✅ Required -->
<button class="ProductFooter-addToBasket">Add to cart</button>
```

### 2. Block = PascalCase, Element = Block-element

```html
<section class="BestSellersBooks">
  <h2 class="BestSellersBooks-title">Best sellers</h2>
  <a class="BestSellersBooks-moreLink" href="/books/best-sellers">See all</a>
</section>
```

### 3. `data-*` is for dynamic state/parameters (JS-driven)

```css
/* ✅ Allowed: Block dynamic state influences its own elements */
.Modal[data-open="true"] .Modal-overlay { opacity: 1; }

/* ❌ Forbidden: using data-* as a substitute for "design-system variants" */
/* .Button[data-variant="primary"] { ... } */
```

### 4. Cascade is restricted

```css
/* ✅ Allowed: Block state → its own elements */
.ProductCard[data-expanded="true"] .ProductCard-media { transform: scale(1.05); }

/* ❌ Forbidden: cross-block cascade */
.Sidebar .ProductCard { ... }
```

## 🧪 Use Cases

### Element → Block Promotion

```html
<!-- Before: simple element -->
<div class="Slider-header">...</div>

<!-- After: autonomous Block (reusable) -->
<header class="SliderHeader">
  <h2 class="SliderHeader-title">...</h2>
  <button class="SliderHeader-cta">...</button>
</header>
```

**When to promote?**

- Element contains structured children
- Must be reusable elsewhere
- Has independent logic

## 💡 Philosophy

### 1. HTML describes role, CSS describes presentation

```html
<!-- ❌ Anti-pattern -->
<div class="flex justify-center bg-blue-500 p-4">

<!-- ✅ ROCS -->
<div class="Card-header" data-variant="primary">
```

### 2. Readability over brevity

**Code is read 10× more than it's written.**

### 3. Preprocessors are mandatory

Helpers (`visually_hidden`, `flex_center`...) are **mixins**, never HTML classes.

```scss
// ❌ Forbidden
<div class="visually-hidden">

// ✅ Required
.ProductCard-info {
  @include visually_hidden;
}
```
